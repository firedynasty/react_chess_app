Updates — 09/08/26
==================

tree_viz.py
-----------
- Openings Stats tab: sortable W/D/L table per ECO+opening (Games, W/D/L,
  Win%, bar) with an opening-name filter box. Respects the time control and
  date filters. Text columns sort A-Z on first click, Games/Win% high-low.
- Opening detail modal: click any table row -> board of the variation's
  position, formatted move sequence (1. d4 d5 2. c4 Nc6), a click-to-copy
  --position "..." string, W/D/L summary bar, and its game list with View
  (PGN). Distinguishes variations that share one ECO code (e.g. two D07
  Chigorin lines get different positions). Row clicks are index-based so
  apostrophes in opening names can't break the onclick handler.
- Position jump input (tree view): accepts d4 d5 c4, 1. d4 d5 2. c4, or a
  pasted --position "d4 d5 c4" string and navigates the tree there. Stays in
  sync with the breadcrumb; X button resets to root. Built for a two-tab
  workflow: openings table in one browser tab, tree in the other, position
  string carried across via clipboard.
- PGNS data embedded in the HTML now includes opening_moves (SAN list to the
  deepest ECO match) and opening_fen per game.
- Fixes: Escape closes the opening modal (PGN panel takes priority when both
  are open); PGN panel z-index raised above the modal veil so View works from
  inside the modal.
- Eval bar in PGN viewer: 14px bar to the left of the board reads [%eval]
  annotations already embedded in the annotated PGN by Stockfish. Dark fill
  (#111) rises from the bottom for white's advantage; light background
  (#d0d0d0) at top represents black's advantage. Sigmoid mapping used for
  smooth 0-100% conversion (score / 3 factor). Handles mate scores (#N) with
  a 97%/3% pin. Board shrunk from 380px to 374px to fit within the panel.
  Root cause fix: pgnParse() was stripping all [...] patterns (including
  inline [%eval] and [%clk] annotations) before tokenization. Fixed regex
  to /^\[.*?\]\s*$/gm so only standalone PGN header lines are removed.

Regenerate with the usual: python tree_engine.py && python tree_viz.py
(run from within data/tttstanley/ — no username argument needed when inside the bucket folder)


annotate.py  (new script)
--------------------------
Standalone Stockfish annotator for PGNs that were not ingested through
ingest.py (e.g. Lichess games, games played against the computer).

- Annotates every .pgn in a directory with [%eval] comments, ?!/??/? glyphs,
  and best-line variations — identical output to the main pipeline.
- Skips files that already have [EngineAnalysis] header (safe to re-run).
- --build flag: after annotation, merges PGNs into games.pgn, runs
  tree_engine, and runs tree_viz — all in one command. No separate steps needed.
- Supports Lichess and Chess.com game IDs (tree_engine._game_id updated to
  handle lichess.org URLs including IDs with underscores, plus GameId header).
- Game list display fixes for Lichess games (no MyColor/MyResult headers):
    - Result shows raw "1-0" / "0-1" / "1/2-1/2" instead of defaulting to "Draw"
    - Winner name shown after result (e.g. "1-0 FirebirdBot")
    - Site label shows "lichess.org" instead of hardcoded "chess.com"
    - TimeControl "-" (correspondence/no TC) hidden instead of shown as "(-)".

Usage:
    # Annotate + build tree viewer in one shot
    python annotate.py against_computer/pgns/ --build

    # With custom depth / parallelism
    python annotate.py against_computer/pgns/ --depth 12 --parallel 2 --sf-threads 4 --build

    # Annotate only (no tree rebuild)
    python annotate.py against_computer/pgns/

Note: "From Position" games (custom starting FEN) are annotated and appear in
the games list but cannot appear in the opening tree — they start from a
non-standard position.
