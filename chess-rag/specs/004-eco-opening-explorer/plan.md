# Implementation Plan: ECO Opening Explorer

**Branch**: `004-eco-opening-explorer` | **Date**: 2026-09-19 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/004-eco-opening-explorer/spec.md`

## Summary

Build a standalone, self-contained reference page — `eco_explorer.html`, generated by a new `eco_explorer.py` — that lets a user browse the full ~12,000-line ECO classification by volume (A–E), by code (e.g. "C20"), by name/family search, or by move-sequence sort (a plain sort on each line's moves, which as a side effect keeps a line's longer continuations adjacent even across codes). Selecting a line opens a detail panel matching `against_computer/tree_viewer.html`'s existing opening-detail modal (CSS-grid board + move list), extended with per-ply step-through (forward/back, matching the PGN modal's `pgnJump`/`pgnGoNext`/`pgnGoPrev` pattern). This is a standalone lookup tool with no tie to played-game data — no copy-to-clipboard/reuse-elsewhere feature, no game stats, nothing that connects it to the played-games tree. The page is entirely client-side (no server/API dependency) and ships its data embedded as a JSON literal, the same way `tree_viz.py` bakes `TREE`/`PGNS` into `tree_viewer.html`.

The only new backend work is a data-preparation step: `eco_openings.json` currently stores only `{eco, name}` per FEN; it needs a `moves` (SAN sequence) field per entry, sourced from the same upstream (`hayatbiralem/eco.json`) `tree_viz.py` already fetches from. That augmented cache is written back to the *same* `eco_openings.json` path so `tree_viz.py`/`lichess_tree_viz.py` (which only read `eco`/`name` and ignore unknown keys) keep working unmodified.

## Technical Context

**Language/Version**: Python 3.11 (data-prep script, matches `requirements.txt`/existing `tree_viz.py`), vanilla JS + HTML/CSS for the generated page (no build step — same as `tree_viewer.html`)

**Primary Dependencies**: `requests` (fetch upstream `eco{A-E}.json`, already a dependency), `python-chess` (already a dependency; used only if move-sequence validation/FEN backfill is needed — see research.md), `chess.js` (already loaded client-side in `tree_viewer.html` via `ensureChessLibs()`, reused here to replay a line's SAN moves into per-ply FEN for step-through — no new client library)

**Storage**: Flat files only. `chess-rag/eco_openings.json` (existing FEN-keyed cache, extended with a `moves` field per entry) is the single source of truth; the generator embeds a derived, page-ready array as a JSON literal directly in `eco_explorer.html`. No database, no API.

**Testing**: Manual verification via `quickstart.md` (no existing automated test suite for the HTML galleries in this repo; consistent with how `tree_viewer.html`/`tree_viz.py` are validated today — open the generated file and exercise it)

**Target Platform**: Static HTML file opened directly in a browser (file:// or any static host) — same distribution model as `tree_viewer.html`

**Project Type**: Single-file static web page + a Python CLI generator (mirrors the existing `tree_viz.py` → `tree_viewer.html` pattern)

**Performance Goals**: All ~12,000 lines browsable/searchable client-side with no perceptible lag on typeahead search (per spec Assumption — no server-side pagination required)

**Constraints**: Must not require a running server or network access to browse (page is fully self-contained once generated); must visually/functionally read as distinct from the played-games tree (FR-006) — reuses the same dark theme/CSS tokens but is a separate file, separate nav, no game-derived stats (W/D/L bars, game lists) and no copy/reuse-elsewhere feature anywhere in it

**Scale/Scope**: ~12,000 named lines across ~500 ECO codes (current cache size); largest individual codes have 200+ lines

**Structure Decision**: New standalone script + generated page at the `chess-rag/` root, parallel to `tree_viz.py` → `tree_viewer.html`, rather than a mode bolted onto `against_computer/tree_viewer.html` or a per-account bucket file — matching the spec's Assumption that this is "a new, standalone page dedicated to reference browsing," independent of any account/bucket. `eco_openings.json` is extended in place (additive field) rather than forked into a parallel cache file, since the two existing readers (`tree_viz.py`, `lichess_tree_viz.py`) only project out `eco`/`name` and are unaffected by an added `moves` key.
